# Architecture

## Selected architecture

A TypeScript Next.js client on Vercel calls a single Python FastAPI service on Render. The service owns synthetic data generation, baseline/model loading, simulation, investigation, and persistence in Supabase Postgres. This keeps the ML and reasoning layer in Python, removes a queue/WebSocket dependency, and is deployable as two public services plus one managed database.

```text
Browser (Next.js / Vercel)
  ├─ GET/POST HTTPS ──> FastAPI (Render web service)
  │                        ├─ scikit-learn + NetworkX + pandas
  │                        ├─ packaged seed/config/model artifacts
  │                        └─ Supabase Postgres
  └─ simulation polling ──> POST /simulation/tick ──> persisted events/incidents
```

## Boundaries and services

| Boundary | Responsibility |
| --- | --- |
| `apps/web` | Rendering, filters, controlled What-If inputs, accessible operator interactions; never computes authoritative incident outcomes. |
| `apps/api` | Domain API, deterministic generators, features, models, graph construction, investigation orchestration, and validation. |
| Postgres | Seeded source facts, derived runs, feedback, and resettable demo state. |
| Build artifacts | Versioned baseline statistics and lightweight sklearn models packaged with the API release. |

## API boundary

REST JSON, versioned under `/api/v1`; OpenAPI is generated by FastAPI. Core endpoints: `GET /incidents`, `GET /incidents/{id}`, `POST /investigations`, `POST /what-if`, `POST /simulation/{start|pause|reset|tick}`, `GET /search`, and `POST /feedback`. `GET /graphs/{incident_id}` returns a display-safe node/edge DTO, never a pickled graph.

The browser supplies `X-Demo-Run-Id`; the API validates every request with Pydantic. CORS permits the configured Vercel origin and local development only. The client reads `NEXT_PUBLIC_API_URL` at build time.

## Full data flow

1. A fixed seed and scenario manifest generate canonical events plus ground truth.
2. Ingest validation normalizes event time, entity, zone, source, and payload into Postgres.
3. Feature jobs derive route, dwell, frequency, telemetry, and sequence features against the historical window.
4. Detectors score deviations; correlation links nearby events in relevant time and space windows.
5. NetworkX builds an incident evidence graph; deterministic rules rank causes and recommendations.
6. API persists the incident, evidence, trace summaries, and feedback; the client renders it with its evidence references.
7. A What-If request runs the same pure pipeline in a temporary run and returns its result without mutating baseline history.

## Reliability choices

No background worker, queue, or streaming broker is required. Live mode uses browser polling every 2–5 seconds; one server-side tick advances a seeded clock idempotently. API health and `/ready` confirm model/artifact availability. Schema migrations run in CI/release before the API starts.

## Proposed repository structure

```text
opsintel/
├── apps/
│   ├── api/                 # FastAPI domain API and Python ML/reasoning layer
│   └── web/                 # Next.js operator experience
├── packages/
│   └── contracts/           # Generated/OpenAPI-derived TypeScript types when needed
├── data/
│   ├── fixtures/            # Versioned seeded event/scenario manifests
│   └── artifacts/           # Small versioned baseline/model artifacts
├── docs/                    # Product and implementation decisions
├── tests/
│   ├── api/                 # Python unit, integration, scenario tests
│   ├── web/                 # Component and browser tests
│   └── fixtures/            # Determinism/evaluation assertions
├── scripts/                 # Seed, artifact-build, and evaluation commands
├── .github/workflows/       # CI
└── render.yaml              # Render API blueprint (added during deployment phase)
```

This is a small monorepo: one deployable frontend, one deployable Python backend, shared contracts only when generated from the API, and all reproducibility assets visible to reviewers. It avoids premature packages/services while preserving clean boundaries.
